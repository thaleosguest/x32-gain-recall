# Changelog

Format : [SemVer](https://semver.org/lang/fr/). Historique reconstitué à partir des étapes de développement.

## [1.5.0]
- **Fusion en un seul exécutable** : `X32_Gain_Float.exe` disparaît en tant que fichier séparé — la fenêtre flottante est maintenant intégrée à `X32_Gain_Recall.exe` (drapeau interne `--float`, utilisé automatiquement par le bouton « Float » du navigateur). Installation simplifiée à un seul fichier à télécharger et double-cliquer. Sous Windows, `CREATE_NO_WINDOW` évite qu'une fenêtre de console parasite s'ouvre à côté de la fenêtre flottante quand elle est lancée depuis le bouton. `x32_gain_float.py` reste utilisable seul en Python source (`python x32_gain_float.py`) pour qui préfère cet usage ; `x32_gain_recall.py` reste lançable sans tkinter installé quand on ne se sert pas du mode `--float` (import tkinter différé, pas en tête de fichier).
- Fenêtre flottante — barre de titre réorganisée pour le tactile : boutons repli (▾/▸) et taille (−/+) déplacés à **gauche**, agrandis (plus de marge interne cliquable/tapable). Nouvelle zone de glisser-déposer dédiée (pointillés, au milieu de la barre), toujours large même fenêtre repliée — avant cette version, les boutons occupaient presque toute la largeur de la barre de titre et ne laissaient que de minces interstices pour saisir et déplacer la fenêtre au doigt, surtout gênant une fois repliée.
- Le code d'accès réseau local (`--lan`) est maintenant affiché directement dans l'interface web (en haut à droite), en plus du terminal — plus besoin de retrouver la fenêtre de console pour le lire.
- Bouton « Float » : quand l'appli principale tourne en mode `--lan` protégé par un code, la fenêtre flottante ouverte par ce bouton n'affiche plus l'écran de connexion — elle hérite directement d'une session valide (le navigateur qui a cliqué le bouton est par définition déjà authentifié). Toujours nécessaire de taper le code à la main pour `x32_gain_float.py` lancé indépendamment (double-clic, raccourci, terminal).

## [1.4.4]
- Nouveau bouton **« Float »** dans la barre du haut du navigateur : lance `x32_gain_float.py` (ou `X32_Gain_Float.exe` si l'appli principale tourne elle-même en `.exe`) en tant que processus séparé, sans avoir à chercher le fichier à la main. **Important, ce n'est pas symétrique avec l'accès tablette** : ce lancement se fait sur la machine qui exécute `x32_gain_recall.py` — pas sur l'appareil qui a cliqué le bouton. Cliqué depuis le navigateur d'une tablette connectée au serveur via le réseau local, le bouton ouvre (ou tente d'ouvrir) la fenêtre flottante sur le PC serveur, pas sur la tablette, qui ne peut de toute façon pas exécuter un exécutable Windows ou un script Python. Utile uniquement pour qui clique depuis le navigateur de la machine qui héberge déjà le serveur (cas typique : PC qui héberge aussi la LV1).

## [1.4.3]
- Fenêtre flottante — le panneau **Scènes** permet maintenant de **sauvegarder** une nouvelle scène (champ nom + bouton, capture tous les gains actuellement lus sur la console, pas seulement la banque affichée), en plus de les rappeler. Jusqu'ici seul le rappel était possible depuis le float. Partage le même fichier `x32_presets.json` que le navigateur dans les deux modes (serveur et `--direct`).

## [1.4.2]
- Fenêtre flottante — potard plus adapté au tactile : sensibilité du glisser réduite par défaut (0,10 dB/px, était 0,25 ; réglable avec `--sensitivity`), et la valeur en dB est maintenant cliquable pour taper le chiffre exact au clavier plutôt que de toujours glisser.
- Fenêtre flottante — boutons **Scènes** et **Routing** dans la barre de titre : ouvrent un panneau sous les potards (la fenêtre s'agrandit) listant respectivement les scènes de gains et les profils de routing, avec confirmation avant chargement. Volontairement simplifié par rapport au navigateur : le rappel de scène ne touche jamais le 48V, et le routing ne touche que le routing E/S (jamais le patch de sortie) — pour un contrôle plus fin, utiliser le navigateur.
- Fenêtre flottante — bouton ▾/▸ pour **replier/déplier** toute la fenêtre en une simple barre de titre, pour libérer de la place sur l'écran de la LV1 quand on n'a pas besoin des gains.

## [1.4.1]
- **Correctif important sur `x32_gain_float.py`** : la v1.4.0 ne proposait aucun moyen de se connecter à la console *depuis la fenêtre flottante elle-même* (il fallait passer `--ip`/`--sim` en ligne de commande au lancement) — ce qui la rendait inutilisable pour qui double-clique dessus sans argument. Corrigé :
  - La fenêtre flottante se connecte maintenant **par défaut à l'appli principale `x32_gain_recall.py` déjà lancée**, via son API HTTP locale (port 8032 par défaut, réglable avec `--port`) : c'est littéralement la même connexion OSC, le même état (gains, 48V) que dans le navigateur — se connecter depuis l'un connecte aussi l'autre. Gère automatiquement l'écran de code d'accès si l'appli principale tourne en mode réseau local protégé (par défaut depuis la 1.3).
  - Nouvelle barre de connexion visible dans la fenêtre flottante : champ IP, boutons **Connecter**, **Scanner**, **Démo** — mêmes actions que dans le navigateur.
  - Nouveau sélecteur de banque direct (menu déroulant : Local 1-16, Local 17-32, AES50-A 1-16, etc.) en plus des flèches ◀▶.
  - Option `--direct` pour retrouver l'ancien comportement (connexion OSC indépendante, sans l'appli principale, avec `--ip`/`--sim`) pour qui ne veut pas lancer le navigateur du tout.
  - Les erreurs de démarrage s'affichent maintenant dans une fenêtre (au lieu de disparaître silencieusement) : l'exécutable `.exe` est compilé en mode `--windowed`, sans console visible pour voir une éventuelle erreur Python.

## [1.4.0]
- Retrait de la sonde OSC en lecture seule (« Setup console ») ajoutée en 1.3 : elle n'a pas donné de résultat utile pour la source d'horloge et n'est plus affichée. Le mécanisme de lecture générique (`/node`) reste utilisé en interne par le Routing.
- Nouveau bouton « Scanner » (barre du haut) : diffuse `/xinfo` en broadcast UDP sur le port OSC (10023) et liste les consoles X32/M32 qui répondent, pour éviter de taper l'IP à la main. Le champ IP manuel reste disponible en toutes circonstances (le scan peut échouer sur un réseau qui filtre le broadcast entre appareils — Wi-Fi « AP isolation », VLAN, pare-feu). **Non vérifié sur une vraie X32 en dehors du simulateur** : le simulateur intégré ne répond pas au broadcast (il n'écoute que sur 127.0.0.1, par construction), donc seul un test sur le réseau réel du prochain lancement confirmera que ça fonctionne derrière votre matériel réseau (switch/Wi-Fi/routeur) — rien dans la documentation OSC non-officielle ne décrit la découverte réseau ; la technique broadcast + port 10023 s'appuie sur une capture Wireshark indépendante rapportant le comportement de X32-Edit, pas sur une spécification officielle.
- **Nouvelle appli compagnon `x32_gain_float.py`** (fenêtre séparée, exécutable `X32_Gain_Float.exe` à part dans les Releases) : une fenêtre sans bordure, toujours au premier plan, affichant une banque de 16 voies en mode réduit (potard de gain, valeur en dB, bouton 48V, diode de niveau — pas de faders). Pensée pour être glissée et redimensionnée à la main dans l'espace vide de la LV1 entre la rangée A/B et la rangée Ø. Se connecte en direct à la console (OSC), indépendamment de l'appli principale ; réutilise son client OSC pour ne pas dupliquer la logique de lecture des gains/48V/niveaux. **Limites assumées, pas de solution fiable trouvée pour faire mieux** : pas d'alignement pixel-parfait automatique avec la fenêtre LV1 réelle (dépend de votre résolution d'écran et du zoom de la LV1, inconnus d'ici) — largeur de voie et position se règlent à la main (molette haut/bas glissée en bas à droite, boutons −/+) et sont mémorisées pour le prochain lancement ; la diode de niveau n'est PAS le vrai détecteur de clip matériel de la X32 (aucun chemin OSC documenté ne l'expose, même limite que l'horloge en 1.3) — c'est un seuil sur le niveau mesuré (−3 dBFS par défaut, réglable avec `--clip-db`).

## [1.3.0]
- Interface adaptée au tactile : cibles agrandies (boutons +/-, phantom, pilules...) sur tablette/téléphone, sans changer l'affichage sur PC/souris. Les curseurs de gain utilisaient déjà les Pointer Events (glisser au doigt fonctionnait déjà).
- Onglet Routing : nouvelle sonde OSC en lecture seule (« Setup console »), pour interroger un chemin OSC quelconque sur la console (ex. tester si l'horloge est exposée en OSC) sans jamais rien modifier. Aucun chemin documenté n'a été trouvé pour la source d'horloge (Internal/AES50-A/AES50-B/Card) dans le protocole OSC non-officiel ni les bibliothèques de contrôle existantes ; ce réglage semble réservé au panneau Setup de la console.
- **L'interface est accessible au réseau local par défaut** (tablette, téléphone, autre PC), sans rien à taper au lancement. Nouvelle option `--local-only` pour revenir à l'ancien comportement (versions ≤ 1.2 : accessible uniquement depuis cette machine, 127.0.0.1).
- Accès protégé par défaut par un **code à 4 chiffres**, saisi une fois sur un petit écran de connexion (clavier numérique tactile, pas de copier-coller) ; une fois validé, une session en mémoire (cookie) garde l'accès. Code sauvegardé dans `x32_lan_config.json` (jamais versionné) ; nouveau code avec `--lan-nouveau-code`. Limitation des tentatives après 5 codes faux (pause croissante, jusqu'à 15 min).
- `--lan-sans-mdp` désactive volontairement cette protection pour qui préfère l'usage sans mot de passe des applis officielles Behringer (X-AIR Edit, M32-Edit) sur un réseau de confiance.
- Numéro de version affiché directement dans l'interface (en haut à droite), plus seulement via `--version`.
